# Release 1.1.97 verification (S68, CORE-32, UPDATE-04)

Source: `4e3396b` (tag `v1.1.97`). Plan S68, spec 1.59.

## Scope

- CORE-32. The owner: "You must have a very complex flow, because with the current index implementation there is no way this behavior makes sense".
  - Analyze space no longer falls back to disk on timers. Removed: the 5-second index wait, the 90-second loading wait and its status timeout, and the 2-second Settle disk walk of recently written folders.
  - A loading store is waited for with no time limit. The footer says so, and Ctrl+R stops the wait and measures on disk.
  - A folder written moments ago is asked for after a 600 ms catch-up. F5 after a change the analysis's watcher saw waits the same 600 ms from that change.
  - Uncovered folders are measured on disk individually. An absent or failing service is measured on disk, with the reason in the footer.
  - SEARCH-10 is revised prospectively.
- UPDATE-04. The owner: "So it did crash on the other update". The 14:41 update left 1.1.95 in place, and setup ran without a log.
  - The updater passes `/LOG` (setup.log in the updates folder) and records the version it started (started-update.json).
  - Setup's DeinitializeSetup logs the failure and reopens Pathweft once its caller has exited. Setup's own failure window appears only when Pathweft cannot reopen.
  - On the next start Pathweft reports an update that wasn't installed, or was installed with a problem. The update window shows setup's reason, the end of the log, Open log, Try again and Close.
