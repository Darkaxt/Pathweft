# Release 1.1.103 verification (S74: RAR-06)

Source: `d004460` (tag `v1.1.103`). Plan S74, spec 1.64.

## Scope

The upstream review of 2026-11-23: rars 0.13.0 adds reader, writer and split-volume fixes and a breaking Rust API change; qualify archive read, write, recovery and the packaged DLL before adopting it. Issue #13, which the review named first, closed in 1.1.100.

- native/pathweft-rars is ported to rars 0.13.0 (`f7098c7b9a1e844555daad1d376fd1f043adba2c`): the `VolumeOutput` sink type, `rars::Timestamp`, `copy_times_by_id`, and the new stored-time accessors. The bridge keeps its operations, JSON and ABI 2; its version op reports 0.13.0. Runtime 0.13.0-pathweft.1.
- Upstream `COPYING` is unchanged (same hash as `vendor/rars/LICENSE.txt`). The lock adds arrayvec 0.7.8, blake2s_simd 1.0.5 and constant_time_eq 0.4.2.
- `Reuse-ReleaseSources.ps1 -RefreshRust` vendors the Rust sources again from the new lock, and `build.ps1` refuses vendored sources that differ from the lock. Without this, a reused source package would have shipped the 0.12.3 sources.
- The contract projects (RarContracts, ArchiveContracts, TransferContracts) target .NET 10 like the app they reference. RarContracts could not restore against it (NU1201).

## Not covered

- The S4 UI trial (`--verify-s4`, the real Compress… dialog and menus) was not run, because it snapshots and rewrites the owner's Windows clipboard. The RAR writer settings it checks are covered by the console contracts above.
- RAR 2.9–4 writing is exercised only through rewrites of the rar4 fixtures. Pathweft creates new archives only in its recorded modern RAR format.
