# Release 1.1.80 verification (2026-11-19)

Release: https://github.com/Darkaxt/Pathweft/releases/tag/v1.1.80 (tag v1.1.80 = ed56333, main and codex/s8-native-delivery).

**Scope:** S56, SEARCH-09 (specification 1.39). The owner asked to replace the Everything integration with the Pathweft index service once that thread allowed it, and to confirm the service works. Everything's client, SDK, bundled engine, monitor and named instance are removed. The index service alone answers pane search, the search popup, folder sizes, the space analyzer, Scoop cleanup and MCP. Setup installs or updates the service silently.

## Service confirmation (installed service, read-only)

Done before the change, against the service the owner had installed (0.1.0, protocol 1): about 12.4 million entries, 721.5 MB private memory. Queries took 45–313 ms and folder sizes about 0.3 s. For comparison, es.exe returned no folder sizes (0 results, exit 8). The index service thread reported dm:today at 22 ms and parent: at 236 ms. Its share checks caught 91 + 21 changes that sent no notification (IS7).

That check also found a service defect. Folders created while the service ran could report a deleted file's size: an empty new folder showed 17,704 bytes, and a 579-byte folder showed 17,259. The index service thread traced it to store.rs, where a deleted record kept its size and a folder later created in the reused record number inherited it. Its fix e9db1a5 (FIX1, regression test `reused_records_do_not_inherit_old_sizes`, 34/34 unit tests) is merged as ed56333 and ships in this release.

## Defects found by the release scenarios

- **Pathweft ended on a malformed index reply.** A `folder_sizes` reply without `sizes` threw KeyNotFoundException through PaneView row sizing. Every reply is now parsed so that a malformed one becomes an ordinary index error and the folder is measured (7f58ecf). The index-service scenario checks this with a stand-in service.
- **Stale checks**, all test-only:
  - The package probe rejected the EverythingToolbar attribution notice. It now matches build.ps1's rule: no Everything engine or SDK member.
  - Sizing119 still passed the removed SpaceScan argument.
  - The widget expected the column "Modified", which has been "Date modified" since S50 (COLS-02).
  - The widget opened dist/1.1.1's source zip, which the release retention rule removed. It now creates its own archive and waits, bounded, for the index to list it.
  - The indexed-row check created its fixture while a pane watched it, and NTFS delivered late change notifications for the fixture's own writes. Each correctly made Pathweft measure the folder. The fixture is now created with the panes parked elsewhere, and the check reopens it until no notification is pending (bounded 30 s).

  These are fixed in 90a86eb and 5c00388.
