The donor's all-storage LibreHardwareMonitor inventory opens broader hardware
infrastructure and the pinned DiskInfoToolkit watcher; it also pairs Windows
health with duplicate friendly names by enumeration order. This integration uses
the exact Windows volume extent/device number and inbox COM WMI/read-only storage
queries instead. There is no LHM/PawnIO dependency, driver installation, sensor
inventory watcher, second collector or model-name matching. Virtual/network and
ambiguous multi-device paths do not borrow host/cache-disk measurements.

Native NVMe decoding follows Microsoft's
[health-log layout](https://learn.microsoft.com/en-us/windows/win32/api/nvme/ns-nvme-nvme_health_info_log),
[controller identification](https://learn.microsoft.com/en-us/windows/win32/api/nvme/ns-nvme-nvme_identify_controller_data)
and [Windows query protocol](https://learn.microsoft.com/en-us/windows/win32/fileio/working-with-nvme-devices).
Lifetime writes use 128-bit 512,000-byte data units and decimal TB; temperatures
convert Kelvin to Celsius, wear is percentage used, and power-on duration is
hours. Returned buffer lengths/offsets and physical-device identity are checked.
Non-NVMe devices show available Windows reliability facts only. Unknown health
does not become Healthy. Current health is distinct from the historical cursor.

Health reads have one in-flight owner and a one-minute refresh cadence only in
the visible Drive investigation. Leaving/closing drains original native work;
stale identity results cannot replace a new drive. Privileged reads reuse the
approved helper and never automatically request UAC. An actual permission failure
offers the existing shared-administrator action. Background throughput and latency
reuse the existing one-hour/3,600-sample ring and bounded disk retention.

The Huashu design contract preserves Pathweft's existing investigation, theme,
typography and interaction model: one current-drive health header; read/write
curves above latency with active time; one shared time axis/cursor/overview;
compact split labels at narrow widths; controls and tables remain scrollable.
Dark/light100/150-percent at1400/820-DIP widths are required rendered checks.
No extra window or all-drive dashboard is introduced.
