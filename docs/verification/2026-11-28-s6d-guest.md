# S6d guest verification: Start menu visual styles from StartAllBack

Source: `9ccdcb4` and the corrections in `07e0470` (debug builds, ticket 12afdcc6 attempts 1 and 4). Plan S6d, spec SAB-07 (visual styles). Released as 1.1.116.

## Guest

- Coordinator Windows Sandbox gate, 4096 MiB, networking off; seven sessions. Read-only inputs: the host .NET runtime and the debug build output.
- StartAllBack 3.9.28 installed in the guest with its default configuration (no Cache folder, licensing or registry state copied). Styles were switched by writing StartAllBack's own values (`AlterStyle`, `FrameStyle`, `StartMenuAlpha`, `StartMenuBlur`, Personalize `AppsUseLightTheme` and `SystemUsesLightTheme`).
- The owner's setup is the Default style, dark, alpha 128, blur 1. The three Welcome presets give the Default (Proper 11), Plain8 (Kinda 10) and Windows 7 (Remastered 7) menus, so those three menus cover them.
- Each style was captured with StartAllBack's menu open, then with Pathweft's (`Pathweft.exe --agent`, Start menu setting on), with and without a hovered item and with search text.

## Results

| Area | Case | Result |
|---|---|---|
| Ownership | Pathweft's helper owns Win; its menu opens instead of StartAllBack's | pass |
| Default, dark | Layout, columns, separators and panel colours as StartAllBack's | pass |
| Windows 7 | Frame, columns and hot parts from the installed style file, layout close to StartAllBack's | pass |
| Plain8 | The style applied to the open menu | pass |
| Live change | Switching to Windows 7, then Plain8, in dark mode applied to the open menu without a restart (carried from S6c) | pass |

Found by this check, fixed in `07e0470`:

- Glyph icons (search lens, clear, chevrons, power, Sign out) were empty: their private-use characters were lost when the files were rewritten. They are now `\u` escapes. A host render of the corrected build shows the lens, power and chevron glyphs.
- The Default search box is rounded with the lens drawn in it; a style's search box shows its own lens part.
- The picture ring is hidden while a hovered item's icon is shown, for styles too.
- The new-program highlight uses the window glass colour, as StartAllBack does, instead of the accent tint.

The corrected build was not captured again in the guest: after the helper restart on it, screen capture in the guest failed ("The handle is invalid") and the session was ended. Its changes were checked with a host render.

## Not covered, tracked

- Issue #17: a grey square behind the hovered item's icon in the picture area, cause not yet known.
- Light mode and the styles' search parts were captured for StartAllBack only; Pathweft's side of those was not compared in the guest.
- The owner's machine: DPI at his scaling and Pin/Unpin (S6e).
