## Why TeraCopy still wins on small files

A separate diagnostic uses the same 100 × 4,096-byte source and adds scoped I/O
hooks in both programs. Its timing is excluded from the performance table.
Both children exit successfully; parent SHA-256 verifies all outputs; no scoped
handles remain at exit. NT/Win32 layers are counted separately, not added.

| Observed operation | TeraCopy | Pathweft direct |
| --- | ---: | ---: |
| Attempted scoped NtCreateFile/NtOpenFile calls | 515 | 3,715 |
| Source / target NtClose calls | 297 / 211 | 1,306 / 1,902 |
| Process D: GetVolumeInformationW calls | 1 | 201 |
| Scoped GetVolumePathNameW calls | 1 | 201 |
| Target FILE_WRITE_ATTRIBUTES opens for explicit timestamp setters | 0 | 303 |

Pathweft calls `NamedStreams` for each source/target inventory; each repeats volume
path/capability discovery, including native opens. `ApplyMetadata` makes three
separate .NET timestamp setter calls per file/directory, each opening the target.
Destination ancestry checks and metadata/source-state checks add other per-file
queries. These are concrete overhead sources; the trace does not assign an exact
fraction of wall time to each call.

Pathweft explicitly rereads the source to calculate its verification hash after
CopyFileEx, then reads the target. TeraCopy's trace observes one payload's worth
of source reads during copying and one target payload during checking, with no
scoped mappings or pending reads observed. Hashing source buffers while copying
is consistent with that evidence, but its packed internal implementation was not
recovered. Native/offloaded CopyFileEx I/O can bypass user-mode read hooks, so the
trace must not be presented as a complete count of kernel/device bytes.

These findings justify considering batched timestamp updates and eliminating
redundant capability discovery in bounded future optimization. Hash-during-copy
would require a different copy path with preservation/cancellation consequences.
No additional engine rewrite, global capability cache, new protective workflow or
unmeasured speed claim was added for this investigation. Optional opportunities
are not unmet S5 acceptance or required tracked deferrals.

Raw counters/source scripts are retained in `TeraCopy-profile01` and
`Changed-profile01`; their original generic timing text predates profile-specific
labeling and must not override the actual loaded I/O hooks. The waiter now labels
profiling receipts explicitly. Loaded-script provenance is retained by REA records
`ev_c6a0821efba5a56ae5c6b0faa47ae2746c7f008718a0bf17586179f923ac214a`
and `ev_8a3f93d9ff4ceca41855524e5ae6d508909f22bea77264a1ddcb7007ac95adf9`.
