## Defects found by validation

### Product defects

Each was found by the `browse` scenario and fixed in c4cfcef.

- **BROWSE-05: saving one folder's view changed every other folder.** Changing the view in a folder without a profile also set the pane's default. "Change, then Save for this folder" therefore changed every other unprofiled folder. The first save now puts back the defaults captured when the folder was opened.
- **BROWSE-08: the terminal pulled the pane to the user profile.** The terminal started in the user profile, and its first OSC 9;9 report navigated the pane there. Now:
  - the terminal syncs before the panel is shown;
  - Follow() is retried when the prompt becomes empty;
  - a report navigates the pane only when the folder differs from the terminal's previous one.
- **BROWSE-09: no-replace WebDAV uploads overwrote files.** rclone ignores If-None-Match, so these uploads overwrote an existing file. The upload now does a HEAD first and refuses an existing name.

### Package and test defects

- **Settings reset self-test (found by the package checks).** The new `terminal.height` setting was in no reset card and not in `NotReset`. It is the panel's remembered height, like `previewwidth`, so it joins `NotReset` (c382961).
- **Stale Debug-test expectations** in BrowseVerification and the hidden trial (98eba16): browse may activate only on a verified private desktop on WinSta0.
- **Stale vendor runtime manifest.** The first packaging failed because of it: BouncyCastle 2.6.2 to 2.7.0, plus the SSH.NET, terminal and ConPTY graph. It was regenerated (ff72d27).
- **Stale package probe.** It expected 7 Settings categories. S21 adds Actions and Privacy, so it now checks for 9 (7f9bfd1, probe only).

Every failure found outside the gate was recorded with build-fail before its correction on the original ticket.

## Pending issue: indexed subfolder size can lag a fresh write

The first package-check run on the final delivery failed one check: "Delivered current-pane toggle exposes actual tree/size/usage/status with the correct recursive total". The previous run, on identical product code, passed it, and the rerun passed it as well.

The cause is in SpaceScan.Walk. The fixture writes `nested\payload.bin` and starts the analysis at once. When the installed index already lists `nested` but has not yet read the file's change record, its folder size is taken as final, and the total misses the 579 bytes.

This is index-backed sizing from S56 (SEARCH-09), not S21. It is a pending issue for the next release:
- **Fix:** before trusting an indexed size, check its freshness, for example against the folder's last write.
- **Verify:** repeat the Sizing119 check with a write immediately before the analysis.
