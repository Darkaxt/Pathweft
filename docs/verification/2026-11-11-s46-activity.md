## 1.1.55 regression fix (same day)

- Field report on the installed 1.1.54: opening Settings closed Pathweft, and the
  update did not reopen the app. The .NET Runtime event showed
  `FileNotFoundException (0x80070002)` from `StartupTasks.Owned` via
  `RecorderRegistered`: the COM binder reports a missing task as
  FileNotFoundException, not COMException. Setup's `--resume-agent` hit the same
  lookup, exited 1, and Setup therefore skipped reopening the app (the Win+E helper
  had already restarted). Profile-based harness runs skip the real lookup, so they
  missed it.
- Fix (commit 8c6abd8): a missing task reads as absent; recorder resume cannot fail
  helper restoration. The default harness now checks the real missing-task lookup.
- Gate stage s46-hotfix-1.1.55: Debug, Release publish and PackagedChecks probe exited
  0 with verified tree exit. Default harness 46/46 (first attempt stalled in the
  Everything search checks before the new check and was rerun once). Sources
  verified (2,146 git blobs); package checks 2,420 passed, 0 failed. Published at
  https://github.com/Darkaxt/Pathweft/releases/tag/v1.1.55; all six downloaded assets
  match SHA256SUMS.txt and the local package.
- Installed 1.1.54 (read-only check): the first start migrated Start with Windows to
  the task `Pathweft startup <SID>` (priority 4, standard rights, exact `--tray`
  action) and removed the `Pathweft` Run value; `Pathweft Agent` remains.
- Startup UAC cancel (installed 1.1.58, 2026-11-12 17:32, user-operated): the owner
  launched Pathweft and rejected the administrator prompt. The window opened
  normally (startup.log: window 3,863 ms, files 3,902 ms), one `Pathweft.exe` front
  process with no arguments, the shield read "Standard access - switch to
  administrator" (read-only UIA), and the agent and elevated recorder processes from
  the 14:55 update kept running. The approve case and a sign-in start remain.
