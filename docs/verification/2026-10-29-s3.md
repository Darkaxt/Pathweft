## Corrections established from evidence

- An early PDF assertion confused physical pixels with DIPs. Windows produced a
  valid second-page bitmap at 1960 pixels for a 1400-DIP request. Microsoft's
  [DestinationWidth documentation](https://learn.microsoft.com/en-us/uwp/api/windows.data.pdf.pdfpagerenderoptions.destinationwidth?view=winrt-26100)
  defines the units as DIPs. The corrected check requires actual second-page
  content and its nonempty bitmap; production paging needed no workaround.
- The first F3D reset test found that resetting bounds preserves camera
  orientation. The module now saves its initially fitted camera and calls the
  native reset-to-default operation. The same orbit/zoom/reset workflow passed.
- File-release verification initially awaited one request snapshot while a real
  folder refresh canceled/replaced that generation. Diagnostics showed current
  media still loading, not a decoder error. The harness now drains the owned
  generation chain. The entire workflow and independent settings process then
  passed, followed by the final standalone-absence run. No sleep/retry or
  production preview workaround was introduced.
