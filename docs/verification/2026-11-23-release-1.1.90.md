# Release 1.1.90 verification (2026-11-23)

Release: https://github.com/Darkaxt/Pathweft/releases/tag/v1.1.90 (tag v1.1.90 = b83dd05, main and codex/s8-native-delivery).

**Scope:**
- S61: MONITOR-26 (spec 1.53), from the owner's question "Why is pathweft eating constantly 3 to 4 percent of CPU?".
- Cause, from a dotnet-trace of the owner's 1.1.89 window with the live CPU analysis open:
  - each one-second sample refreshed the panel twice;
  - each refresh reset the process table's view three times;
  - a UI Automation client on the PC listens to the window, so every reset made WPF raise automation events for the rebuilt table;
  - the window process used about 66% of one logical processor, its UI thread about 46%.
- Fix (product source 6d013b5):
  - sort and filter are applied only when they change;
  - the CPU and RAM process tables are ordered in their source collection by moving only rows outside the longest in-order run, replacing WPF live sorting, which moved about 160 of 372 rows per sample;
  - an unchanged process sample or row leaves the rows untouched;
  - the GPU and folder I/O tables are replaced only for a new sample.
- No Help change: there is no new user-facing feature.

## Verification criterion revisions (prospective, assistant-authored)

- The fixture bound of 10% of one processor was unattainable: the fixture's live panel alone measured 6.5 to 18.4% with no client. It became "the client's added cost above the no-client baseline is at most half of the reset cost". The absolute check moved to the owner's installed window: at most half of its 1.1.89 measurement.
- The reset comparison first replayed three resets per sample. 1.1.89 performed six (two refreshes of three), so it now replays six.
- The in-process UI Automation client was unreliable: it lost events and stalled the UI thread. The measurement now uses an out-of-process client, a Windows PowerShell process with a compiled UIAutomationClient listener with the same subtree handlers and cache, as real accessibility, text and capture tools are.
