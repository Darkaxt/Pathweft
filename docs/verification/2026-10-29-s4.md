## Corrections established during verification

inventory. It now uses the shared inventory. Physical archive files are
distinguished from entries inside them for normal copy and preview.

The pinned wrapper had documented null-directory marker dereferences and leaked
streams opened by CompressFileDictionary. The reviewed source patch fixes their
actual owners; native empty-directory and immediate exclusive-handle tests pass.

Transfer clipboard readers now use actual native formats consistently. Explorer
was observed holding the clipboard during rapid test actions. The finite
scenario waits for actual availability only for read operations or a Paste
rejected before any queue dispatch, without a deadline or arbitrary delay.
Full snapshots, restoration and independent hash verification use separate STA
processes; a newer clipboard owner is preserved. Earlier OLE restoration failures
were diagnosed and original text/locale formats recovered and independently
checked before further tests.

## Boundaries and closure assessment

These are actual WPF listener/rendered checks, native library IO, OS clipboard IO
and a real controlled consumer. They do not establish physical context-popup
placement or the UI of an arbitrary Windows default application. RAR5's stored
fixture and CAB were qualified; every codec/encryption/volume variant was not.
Encrypted edits and split-volume browsing are explicitly unsupported capabilities,
not unfinished promised write support. See ARCHIVES.md.

The closure review resolved the obsolete ZIP reader, independent Compress/Extract
workers and missing move-source volume reservation. No further material current-
stage consolidation is required. S4 has no remaining acceptance blocker or
tracked deferral. S5 owns its separately specified REA transfer study/revalidation;
S8 owns final combined distribution, complete matching source and package checks.

scratch. The first unused review was discarded without deletion when further
