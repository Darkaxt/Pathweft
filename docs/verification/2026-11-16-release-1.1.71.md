### Defects found by this release's tests and fixed before publication

- **Copying out of solid archives wrote only folders.**
  - What failed: copying a folder out of a solid archive (most .7z) through Transfers wrote only its folders, and a 7z entry never reached preview.
  - Cause: SharpSevenZip's `ExtractFiles(callback)` throws "Solid archives are not supported."
  - Fix: `Archive.Pass` decodes a solid container in one native `ExtractFiles(directory, indexes)` pass into a hidden staging folder beside the targets. It checks each file's size, verifies the stored CRC on verifying jobs, then publishes it. Other containers stream entry by entry. The bug was never shipped; 1.1.70 did not use this API.
- **A damaged .7z or .rar asked for a password.**
  - Cause: the new password-on-opening rule judged by extension only.
  - Effect: the S4 trial was blocked on the dialog for `broken.7z`.
  - Fix: `Archive.HidesNames` reads the headers instead, as 7-Zip does. It counts a 7z whose encoded header uses the AES coder, a RAR5 archive encryption header, or a RAR4 main header with encrypted block headers. It was checked on the fixtures before porting: `encrypted.7z` (`-mhe=on`) true; broken, plain, file-encrypted, multipart, RAR and zip false.
- **Stale S4 test lookup.** The S4 transfer-card Cancel lookup still expected TextBlock content. Cards use `TransferActionLabel` since 2026-11-07.
