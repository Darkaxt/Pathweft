  directory, mutex/pipe, agent/startup registry values, shell verb/backup key,
  installer AppId and fork update URLs. Removed automatic upstream profile
  migration and upstream ecosystem-card writes. Isolated profiles reject shell
  registration. Installer execution and update/uninstall remain S5 boundaries.
- Original File Labs, built unchanged from `a8d5a5c`, and Pathweft ran concurrently
  with isolated profiles. The original remained running and its profile sentinel

  window and exited, leaving one Pathweft process. Handoff no longer opens a
  duplicate window after an arbitrary connection deadline.
- Native Everything SDK IPC uses one STA dispatcher/queue for both panes,
  correlated replies, per-pane cancellation/generations and indexed metadata.
  The existing default Everything 1.4.1.1032 GUI/service remained the same
  processes; no second indexer was started or configuration changed.
- Real pane queries returned 620 scoped wildcard hits, retrieved as 200-result
  pages through the final page. Full-index scope included the sibling's 621st
  match. Size descending sorted the entire indexed set before paging. Real regex
  returned 100 matches; Unicode/spaces returned one; grouped OR remained inside
  the subtree. Independent ES CLI comparisons confirmed the first four counts.
  ES's `-path` argument avoids its separate nested-quote command-line grammar.
- Superseding a query could not replace newer empty results. Both panes kept
  separate queries. A result menu revealed its real parent and selected the
  file. F3 on a subsequently deleted indexed file reported an unavailable path
  without opening an editor or executing it. Navigation canceled pending search.
- A real folder notification reproduced a queued refresh restarting search during
  paging. Search/navigation now stop the old refresh and queued watcher callbacks
  check their owner identity. The complete paging workflow passed with that
  pending-notification regression in place. Global file-open shortcuts also
  defer to the scope control; its actual WPF keyboard event passed.
- Focused virtual-origin checks passed: all-index hits from This PC retain real
  file selection/reveal actions; all-index search from a ZIP uses real-path
  dispatch, and leaving search restores archive browsing. Folder-scoped and
  filesystem searches still explicitly require a real folder.
- Explicit live-filesystem mode returned the same 620 fixtures through an
  unindexed UNC path. An unavailable share reported partial/error coverage.
  An unindexed exFAT leaf folder was checked read-only against its actual bounded
  contents; no personal file was modified or opened. Indexed results always
  disclosed that exclusions, unindexed and offline items may be absent.
- Real navigation, selection, new/closed tabs, Enter search, one/two panes and a
  2,400-file listing were exercised. Off-screen rows remained virtualized.
  Indexed rows request shell assets only for realized containers; result folders
  are not recursively measured. Cross-pane Copy and the destination's routed

## Exact remaining blocker

**CORE-02: OS clipboard round trip and physical source -> OLE -> destination
drag remain unverified.** Windows LockApp owned the input desktop. The WPF OLE
clipboard read failed with `0x800401D0 / CLIPBRD_E_CANT_OPEN`, reproduced in a
separate STA process. A physical-input trial could not reach the app. Its test
mouse button was released, the owned trial exited, and the harness now refuses
physical input when LockApp owns the surface or the measured row is unavailable.

Resolution: the user unlocks Windows normally; rebuild/run the finite S1 scenario
and verify actual OS clipboard/drag completion and resource cleanup. Do not
attempt to unlock Windows or replace these checks with routed-event evidence.
S1 acceptance, final reconciliation and S2 progression depend on that result.
There are no tracked deferrals, and no intermediate release is authorized.

Private captures, host paths and machine records are retained under ignored
`.local/` for this unresolved acceptance case. Public evidence is sanitized.
Disposable native/build/fixture output is handled by the installed
transactional-cleanup workflow after the final consumer exits.
