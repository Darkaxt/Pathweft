# Release 1.1.104 verification (S75: CORE-34)

Source: `23412f2` (tag `v1.1.104`). Plan S75, spec 1.65.

## Scope

The owner asked "Did pathweft crash?" and later reported "It crashed again". 1.1.103 ended twice, at 2026-11-25 23:48:54 and 2026-11-26 00:11:10, both times on Copy path from the item menu: unhandled `ExternalException` 0x800401D0 (CLIPBRD_E_CANT_OPEN) from `Clipboard.SetText`. Another program held the clipboard open.

- `ClipboardText.TrySet`/`TryGet` and `MainWindow.PutText`. Every text copy goes through them: the item and archive menus, Ctrl+Shift+C, copy details, Copy as table, checksums, OCR text, remote addresses, report rows and the search widget. So does the checksum clipboard read. A refused copy reports "Nothing copied: ... is using the clipboard. Try again." in the status bar.
- `ClipboardText.Holder` names the program holding the clipboard open when Windows reports its window. Cut/Copy and Paste as file use it too.
