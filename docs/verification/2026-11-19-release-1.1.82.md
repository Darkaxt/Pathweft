Release: https://github.com/Darkaxt/Pathweft/releases/tag/v1.1.82 (tag v1.1.82 = c2572a1, main and codex/s8-native-delivery).

**Scope:** S57, TOOLS-11 and SEARCH-10 (specification 1.41).
- TOOLS-11 is the owner's report of 2026-11-19: the integrated tools were wired for the selection but not for the folder, and PowerToys' own PowerRename entry appeared under More actions.
- SEARCH-10 resolves the 1.1.81 pending issue, where an indexed subfolder size could lag a fresh write.

## Defects found by validation

**SEARCH-10 first applied the two-second settle rule to every indexed size lookup (6936ef2/92025f3).**
- With that rule, `live-indexed-sizes` failed twice with "The ordinary pane uses the indexed total…".
- A direct probe against the installed service found nothing wrong with the service itself: it answered 579 within 171 ms, and the folder write times were normal.
- Pane rows already have a watcher that sends a changed folder to measurement, so the rule is now limited to space analysis, which has no watcher (05d4c23):
  - `IndexedSearch.SettledFolderSizesAsync` is used by SpaceScan and PaneSpace;
  - pane rows keep `FolderSizesAsync`;
  - the live fixture is backdated before the pane watches it.
- The failure was recorded with build-fail before the correction on the original ticket.

**Packaging trap, not a product defect.** build.ps1 requires `<ScratchRoot>\corresponding-sources\source-manifest.json`, so the package needs `-ScratchRoot` set to the stage's scratch (D:\Temp\pathweft-s57).

## Accepted limit

SEARCH-10 checks the direct child folder's last write time. A write deeper in the tree, or a resize of an existing file, does not change that time. Space analysis can therefore still take a lagging indexed size in those cases, for up to the index's journal delay of about 250 ms.
