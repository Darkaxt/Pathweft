### Defects found by this release's tests and fixed before publication

- **Packaged app commands were missing.** The first design enumerated registered verbs and handlers class by class. Explorer's own menu (Shell.Application) also had packaged-app commands such as "Ask Copilot", which that enumeration cannot see.
  - Fix: Pathweft now asks the shell for Explorer's composite menu for the selection (or folder background), with CMF_EXPLORE (and extended verbs with Shift). It removes the entries Pathweft has itself (its own verbs and the New submenu) and takes the rest into its groups.
  - Result: Explorer's rules and order (AppliesTo, Extended, Blocked, multi-selection) now come from the shell itself.
- **Folder parity named some of Pathweft's own commands differently.** Explorer's "Explore", "Open in Pathweft", "Scan with Diskweft" and "Analyze disk space usage with RidNacs" are Pathweft's Open and Analyze space in this folder. The parity check maps those equivalents.
- **A test-only defect: the MENU-05 assembly check matched itself.** The UTF-16 match in Pathweft.dll was inside the check's own failure-message literal. The message was reworded; the program has no other match.
- **Stale test claim about Defender.** An earlier check expected Microsoft Defender's entry. Explorer's own menu has no Defender entry on this PC, so the check now compares against what Explorer actually shows.
