# Release 1.1.95 verification (S66, IDX-03, IDX-08)

Source: `1aee118` (tag `v1.1.95`), plus `47aa726` (test script only). Plan S66.

## Scope

- Owner, after installing 1.1.94: "changing from standard view to administrator view broke the indexing status, as far as I know our indexer runs as admin and we are only filtering out results, so the filtering shouldn't just break".
- Cause: the index service kept the most recent client token per user for scanning that user's folder roots. Pathweft's administrator view connects with the elevated (split UAC) token, which replaced it; the elevated logon session has none of the user's drive mappings, so the rescans of T:, H: and J: failed. The installed service log showed "cannot list ... error 3" for H: and J: on 2026-11-19 and 2026-11-23, and for T: on 2026-11-23. Visibility answers were cached per SID only, so standard and elevated callers shared them.
- Fix (security.rs): an elevated token is never kept for scans (an owner seen only elevated waits for a standard connection); visibility answers are cached per SID, elevation and NTFS security ID. Non-split tokens (UAC off) count as standard. Help (Search coverage) and What's new describe it.
