Pathweft 1.1.71 makes items inside archives work like files on disk (issue #9) and stops copies failing over attributes.

- Inside archives (issue #9):
  - The right-click menu has the same commands as on disk: Open with, Run with PowerShell, Edit, Compare, Rename all, New folder, New file, Paste into folder, Group into new folder, Compress to ZIP or RAR, Checksum, Copy path and Copy name, and Properties (Alt+Enter) with method, CRC-32, ratio and whether the archive is solid.
  - An archive inside an archive opens like a folder, as in 7-Zip; edits are written back into the outer archive in the same job.
  - An archive with encrypted file names asks for its password when you open it; other passwords are asked only when a file is needed.
  - Copying or moving out of an archive, Ctrl+C into other apps and drag-out all run in the Transfers window, with progress, verification against the stored checksums and the usual conflict choices (Keep both keeps the existing file as "name.old"). The separate Extract here / Extract to commands are retired.
  - Read-only archives grey out write commands with the reason.
- Copies: a destination that can't keep attributes (Read-only, Hidden, System or Archive, for example on Google Drive) no longer fails the copy; the job ends with an orange note.
- Recycle Bin: Restore and Delete permanently need a selection.
- Space analyzer: folders are measured on disk when Everything doesn't answer within 5 seconds.
- Maintenance: pip cache cleanup finds a Python that has pip, even when another app's embedded Python (for example SVP's) comes first on PATH.
- Specification 1.29 records this (S4P, ARCHIVE-06..10, TRANSFER-19, BIN-01, SPACE-10).

Update from Pathweft's own updater or run the installer, which requests Windows administrator consent. Pathweft binaries and installer are unsigned; verify the published files with SHA256SUMS.txt and release-manifest.json.
