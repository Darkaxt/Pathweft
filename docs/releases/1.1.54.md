Pathweft 1.1.54 starts sooner at sign-in, asks for administrator access once when it starts, and can record app activity for its performance history.

- Start with Windows now uses a Task Scheduler sign-in task at normal priority instead of a registry Run entry, which Windows starts among the last items. An existing Run entry moves to the task automatically. This needs the Program Files installation; other copies keep the Run entry and Settings says why.
- Pathweft asks for administrator access once, after its window first appears, instead of when the Performance view loads. Browsing never waits for the answer. Settings → Startup → "Ask for administrator access when Pathweft starts" turns this off.
- Settings → Startup → "Record app activity" (off by default) starts a small elevated recorder at each sign-in, approved once through the existing administrator session. It records which programs ran, how they were launched, and their CPU, I/O and peak memory, grouped into workloads such as one build command. No hashes, signatures, blocking or network. Short light processes, such as thousands of compiler steps, are counted in their workload rather than listed one by one.
- The recorder is light: on the test machine it used about 0.02% of total CPU and about 22 MB of memory while 4,500 processes started per minute, with no lost events.
- Pathweft's performance MCP gains five read-only tools: run history, workloads, top consumers, per-app usage and recording intervals. Retention follows the existing performance history setting.
- Maintenance → Startup recognizes Pathweft's own sign-in tasks.

Update from Pathweft's own updater or run the installer, which requests Windows administrator consent. Pathweft binaries and installer are unsigned; verify the published files with SHA256SUMS.txt and release-manifest.json.
