Pathweft 1.1.52 is a reliability and safety release from a full QA review of the implemented features.

- Scoop cleanup now keeps a version whose program is running instead of partly deleting it, and the result names the program that is in use. Versions that are not in use are removed as before.
- Maintenance, file transfers, update cancel, Settings, drive health, archive listing and release, administrator browsing, previews and the performance sampler report expected Windows errors instead of closing Pathweft. A transfer job always finishes, so the queue never stays on a stuck job.
- Opening Pathweft while another launch is connecting no longer stops later launches from reaching the open window. A launch refuses a hand-off channel created by another Windows account.
- Multi-rename refuses names ending in a dot. Archive entry names `CONIN$` and `CONOUT$` are treated as reserved. Package-manager cache counts outside the supported range are reported as unusable output.
- The editor saves a symbolically linked file to its target and keeps the link.
- Setup stops waiting if the desktop helper exits before reporting its result, and the helper exits if Setup is gone.
- The elevated Maintenance worker accepts journals and review folders only from the current profile. Its change lock is restricted to the signed-in user and is shared by normal and administrator windows.

Overwrite in file transfers still replaces the existing file directly; it does not keep a hidden temporary copy.

Update from Pathweft's own updater or run the installer, which requests Windows administrator consent. Pathweft binaries and installer are unsigned; verify the published files with SHA256SUMS.txt and release-manifest.json.
