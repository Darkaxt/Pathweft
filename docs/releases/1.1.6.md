Pathweft 1.1.6 corrects opt-in folder routing so browsing inside an existing
Explorer window remains in that browser. External folder requests still open
Pathweft. A small native 32/64-bit DelegateExecute handler carries the Shell
browser context instead of replacing it with a direct executable command.

Existing intact opt-ins upgrade automatically; disabled integration and later
third-party handlers remain untouched. Disabling restores the previous values.
Settings refreshes folder ownership when activated so an old enabled label does
not remain after the actual handlers change.

Qualified with real Windows folder context-menu invocation, real hidden
ExplorerBrowser navigation, native COM activation, Unicode/spaced folders and
drive roots, both caller architectures, legacy registration migration, exact
prior-owner restoration and the integrated app's hidden checks. No desktop input
or Explorer restart was used. Direct SHOpenFolderAndSelectItems selection remains
outside the supported routing contract described in README; StartAllBack-specific
virtual links remain in the postponed integration stage.

The installer is per-user; the portable package includes the runtime and native
libraries. Pathweft's executable and installer are unsigned.
