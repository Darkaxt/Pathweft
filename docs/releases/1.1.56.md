Pathweft 1.1.56 fixes an update problem found in 1.1.55.

- If a folder was opened while an update was installing, the new Pathweft could start before the update had finished copying its files. It closed at once, the update stopped partway, and from then on no folder opened in any app until the installer was run again.
- Setup now copies the folder handler first, and while Setup runs, folders open in File Explorer instead of starting Pathweft.
- Pathweft also starts normally if that handler is missing, rather than closing.
- Keep both now renames the existing file to name.old.ext (for example report.old.pdf) and puts the incoming file under the original name; a failed or cancelled transfer and Undo restore the original name.
- Added a CRC32 column (column header context menu): archives show stored CRC32 values by default; folders can opt in to lazy background hashing.

If folders stopped opening after updating to 1.1.55, run this installer once; it repairs the installation.

Update from Pathweft's own updater or run the installer, which requests Windows administrator consent. Pathweft binaries and installer are unsigned; verify the published files with SHA256SUMS.txt and release-manifest.json.
